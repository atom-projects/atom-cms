# Nitro, Flash and AIR clients

Atom can open three clients: Nitro, Flash and AIR.

## Nitro

1. Put the Nitro files in `public/`, or on an HTTPS host you trust. When `ATOM_FRONTEND_URL` is set, as on a headless hotel, Atom also trusts that frontend host. For any other host, add its origin to `NITRO_ALLOWED_ORIGINS` in `.env`, as in `NITRO_ALLOWED_ORIGINS=https://client.example.com`.
2. In Housekeeping, under CMS settings, set **`nitro_path`** to the folder that holds Nitro's `index.html`. Do not add the file name. Only the highest rank can change this setting.
3. Set `CLIENT_NITRO_ENABLED=true` in `.env`. This turns on badge external-texts support.

Atom opens the client at `<nitro_path>/index.html?sso=...`. The address holds a login ticket, so `nitro_path` must be a path on this site or a URL on `APP_URL`, `ATOM_FRONTEND_URL` or an origin in `NITRO_ALLOWED_ORIGINS`. Otherwise the client page returns 503 and sends no ticket. The client page only lets its frame load those origins.

If players see "The game client is not configured correctly." (503), open `storage/logs/laravel.log`. Atom writes an error line, at most once every 10 minutes, that starts with `Atom refused the stored nitro_path setting`. It shows the stored value and the value of `APP_URL`. The usual causes:

- `APP_URL` is still `http://localhost`, or it differs from the address players use, such as `https` against `http` or a missing `www.`. Fix `APP_URL` in `.env`, then run `php artisan config:clear`.
- `nitro_path` has no leading slash, as in `client/nitro`. Use `/client/nitro`.
- The client is on another host. Add that origin to `NITRO_ALLOWED_ORIGINS`.

Check these things:

- `renderer-config.json` and `ui-config.json` must load from the folder you chose. A path that starts with `/` points to the host root. A relative path stays inside the client folder.
- Set the client and emulator addresses for your own server.
- Use HTTPS addresses for assets and sockets when your hotel uses HTTPS.

The setting `nitro_path` is the one the built-in theme uses. The old name `nitro_client_path` no longer works.

The client buttons (home, reload, fullscreen and the online count) are off by default. Set **`enable_client_buttons`** to `1` in CMS settings to show them. `GET /api/v1/bootstrap` reports the setting as `clients.buttons_enabled`.

### Home screen app

Both themes let players add the hotel to the Home Screen of their phone. The installed app opens `/game/nitro` in full screen.

- On Android, a banner with an **Install** button appears when the browser offers the install.
- On iPhone and iPad, a banner with **Show me how** explains the steps for Safari, for Chrome, Edge or Firefox, and for in-app browsers such as Instagram.
- A player who closes the banner does not see it again for 14 days.

Atom serves the app manifest at `/manifest.webmanifest`. It uses `hotel_name` and `hotel_description` from CMS settings, the same values as the headless frontend. The icons are in `public/pwa/`. Replace these PNG files to use your own icon, and keep their sizes. `public/sw.js` shows `public/offline.html` when a player opens the app without a connection.

On phones, the client page fits the visible screen when the player rotates the phone or opens the keyboard, and the client buttons stay hidden so they do not cover the client's own touch controls.

## Flash

1. Set `FLASH_CLIENT_ENABLED=true` to show the Flash option in the menu.
2. Set the variables for your client in `.env`. They are `EMULATOR_*`, `SWF_BASE_PATH`, `HABBO_SWF`, `PRODUCTION_FOLDER` and `EXTERNAL_*`. `.env.example` explains each one.

For badge management to edit the Flash external texts:

1. Set `CLIENT_FLASH_ENABLED=true`.
2. Set `CLIENT_FLASH_FILES_PATH` to the client folder, relative to `public/`.
3. Give write access to the external-texts files only.

## AIR

Use AIR when players start the official AIR client from a launcher that points to your domain.

1. Set `AIR_CLIENT_ENABLED=true` in `.env`.
2. Players install the HabboCustomLauncher and set its server to your hotel's domain, the host in `APP_URL`.

With the setting on, both themes show an **Open AIR client** button on the `/me` page. The Atom theme also shows an **AIR client** button in the header. The button opens `/game/air`. That page makes a new login ticket and sends the player to `habbo://hab?server=<APP_URL host>&token=<sso>`, so the launcher opens the client and logs in. A player can open `/game/air` at most 10 times a minute.

Headless sites get the same link from `POST /api/v1/client/launch` with `client: "air"`.

When the setting is off, there is no button, and both `/game/air` and the launch request return 404. `GET /api/v1/bootstrap` reports the setting as `clients.air_enabled`.

Old client guides are listed in [troubleshooting](1.-Installing-Atom-CMS.md#troubleshooting). Their CMS steps are out of date.
